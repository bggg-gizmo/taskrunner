# Task Runner v1.5.1 — Resource Monitor Safety and Release Quality

**Background Gremlin Group — Creating Unique Tools for Unique Individuals**

## Summary

v1.5.1 is a source hotfix that strengthens the v1.5.0 Resource Monitor, preserves existing workflows and the complete vaporwave UI, and updates the public documentation and build metadata. It does not change the Resource Monitor action parameters, terminate external applications by default, or alter stored workflow schemas.

## Changes

1. **PID reuse defense for every guard response.** `Start RAM / VRAM guard` captures the process start identity at activation. At each measurement the monitor checks that identity; if Windows has recycled the PID, the monitor stops rather than recording unrelated memory measurements. For `terminate_owned`, ownership checks still apply independently at termination.
2. **Race-safe stop behavior.** A resource stop requested while the monitor collects a slow RAM/VRAM sample prevents a new warning/cancellation/termination after that stop. The workflow dispatcher preserves a cancellation that races with an explicit `Stop RAM / VRAM guard` action instead of silently proceeding.
3. **Installer rollback safety.** When a Windows upgrade fails during Start Menu or Installed Apps registration, the installer attempts to restore the previously installed application. The old installation is removed only when all registration steps finish. The uninstaller's default data retention remains unchanged.
4. **Release consistency.** Version 1.5.1 is reflected in the application, Settings screen, Windows executable metadata, installer, README badges, changelog, and build banner. The main user guide now covers the current release.
5. **Regression tests.** Added process identity, memory-stop race and Windows installer rollback checks. All earlier tests remain available.

## Windows build validation follow-up

A real Windows 10/11 Python 3.13 build reported four validation failures after the initial v1.5.1 source publication. This source correction retains v1.5.1 and its existing action schema and UI:

- **Backup database:** Close the live and staged SQLite connections explicitly before replacing the target with the validated backup. This releases the destination file lock on Windows while retaining the atomic backup workflow.
- **UTF-8 validation:** Regression tests open the generated JSON workflow schema and the README as UTF-8 instead of Windows CP1252, which silently corrupts Unicode schema labels and can raise a decoder error.
- **Image click regression:** Exercise and mock the native Windows `winmouse.click` path and the non-Windows PyAutoGUI fallback. Runtime Windows multi-monitor input remains unchanged.

The complete Linux source suite remains at **139 passed, 3 skipped**, and all source files compile. The corrected Windows test/build/GUI acceptance still requires execution on the intended Windows system; no Windows EXE is advertised as tested.

## Safety and validation limits

Memory monitoring is opt-in and warning-only by default. NVIDIA compute VRAM is available only where the installed driver reports it. Task Runner cannot guarantee prevention of all out-of-memory failures. The patch was regression-tested on Linux with source-only tests. Windows Qt UI operation, per-process memory behavior, PowerShell rollback, bundled Python/Playwright/OCR, actual NVIDIA GPUs and the compiled Windows EXE must be tested on Windows before claiming a verified binary.

## Windows runtime responsiveness and editor correction

The Windows 11 Python 3.13 source build passed 141 tests and produced an EXE, but subsequent interactive use reported unresponsive **New Task** and **Edit** controls and severe sluggishness. This corrective source update addresses defects missed by the import-only packaged self-test:

- Moves recurring scheduler/database/path polling off the Qt UI thread, keeping normal one-second schedule checks and the existing workflow execution model intact. Dashboard refresh skips nested modal dialog event loops.
- Initializes SQLite WAL mode once when opening a Store rather than re-requesting journal changes during each read, which reduces avoidable contention on Windows.
- Preserves the wizard's exact controls and styles while sizing the window to the actual usable screen. New Task and Edit now display exceptions and append tracebacks to `%LOCALAPPDATA%\TaskRunner\runtime-errors.log`. Other uncaught Qt callbacks are logged there as well.
- Restricts Windows PyInstaller collection to the supported RapidOCR ONNX CPU inference runtime and bundled offline ONNX models, avoiding unrelated optional PyTorch, TensorFlow, Transformers and developer test packages that the previous `--collect-all` pulled from shared Python. **The installed shared Python packages are not deleted or changed.**
- Extends both the Windows pytest suite and the packaged `--self-test` to actually construct the Qt main window, action editor, click **New Task**, save a temporary task, click **Edit**, and verify the edit persisted in an isolated temporary database. Existing OCR model inference and bundled Chromium checks remain mandatory.

No workflow action, persisted schema, user data, executable icon, audio asset, UI component, or archive version was removed. Existing Windows EXEs must be rebuilt to receive these changes. Source-only validation does **not** certify actual Windows desktop responsiveness; the new Windows Qt interactions are verified by the updated Windows build and frozen self-test.
