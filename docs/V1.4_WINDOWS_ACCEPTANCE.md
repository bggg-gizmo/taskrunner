# Task Runner 1.4.0 — Real Windows acceptance checklist

These steps exercise actual Windows functionality. A Linux unit-test pass and a screenshot of a layout diagram do **not** substitute for this acceptance procedure.

1. Run `CHECK_DEPENDENCIES.cmd`. Confirm Python 3.11–3.13 x64, installed `rapidocr` (3.10+), `onnxruntime` (1.22+), PySide6, Playwright, pywinauto and pynput dependencies. Confirm no project-only virtual environment was created.
2. Run `BUILD_WINDOWS.cmd`. Ensure all tests pass, Chromium is bundled, `TaskRunner.exe --self-test` returns success, and the JSON report includes `Offline OCR models bundled and initialized: pass`.
3. Run `CAPTURE_UI_WINDOWS.cmd` and inspect all five **actual** Qt screenshots in `ui-shots`. Compare original dashboard, wizard, Settings, Logs and the new gallery; nothing should be missing or unreadable at 100% and 150% DPI.
4. Run the EXE with a temporary test data directory. Create two small sample workflows. Record actual mouse/keyboard steps in Notepad and stop with **Ctrl+Shift+F12**. Confirm that the prior recorder still operates.
5. Click **▶ Debug replay**. Confirm it pauses before step 1. Run **Step once** and verify only one action executes. Press **Continue** and confirm it completes. Review actual screenshot artifacts in `%LOCALAPPDATA%\TaskRunner\debug-runs`.
6. Construct a failing click, enable **strict targeting**, and verify the engine pauses without clicking unrelated controls. Use **Teach current click…** to select the correct button; press **Retry failed step**. Repeat with two nearly identical on-screen targets to verify ambiguity protection.
7. Test window moves across two monitors, negative desktop coordinates, Windows display scaling at 100%, 125%, 150% and mixed DPI. Verify UI Automation ID and window-relative click behavior.
8. During a task, press **Ctrl+Shift+F11**; the running workflow must cancel. Confirm the hotkey listener stops afterward, and scheduled workers still respect stop requests.
9. Add **Wait for visible text (offline OCR)** and select a region displaying known words. Confirm the text appears across consecutive frames. Test Unicode and the case-sensitive option; disconnect the network to confirm no cloud OCR requirement.
10. Set a **file-event schedule** for a test file. Create, update, and delete it; confirm the intended triggers occur once, no duplicate runs appear, and startup baseline does not fire unexpectedly. Verify that the closed-GUI scheduler has minute-level, not guaranteed sub-second latency.
11. Open **Output Gallery**, choose a folder containing PNGs and text files, preview both, detect identical files, and export a ZIP. Verify SHA-256 manifest contents and that no unrelated data is included.
12. Create a reusable task module, reference it from a workflow, confirm the shared variable appears, and ensure self-referential module cycles are rejected before execution.
13. Store a test secret with **Settings → Local credential vault**, reference it through the vault action, and confirm the task JSON contains only the secret name. Do not use a real password for acceptance. Test another Windows user account cannot decrypt that value.
14. Export a portable `.trpkg` with a reference image and submodule, import it into a separate test data directory, confirm checksums pass, all jobs are disabled, and images and module IDs are correctly remapped. Modify a byte in the ZIP asset and confirm import is rejected.
15. Create a three-action linear workflow where step 1 succeeds and step 2 intentionally fails. Fix its missing prerequisite and click **Resume failed run**. Verify step 1 is not repeated and steps 2–3 finish. Test refusal if the workflow changes or uses unsupported volatile state/branches.
16. Run the original v1.3.0 regression tasks, scheduler, browser automation, file operations and launcher. Ensure the old `old builds/v1.3.0` snapshot remains unchanged and all seven interface sounds still work.
17. Test `INSTALL_WINDOWS.cmd` then uninstall from Windows Installed Apps. Confirm application files/shortcuts/registry/scheduler are removed, while existing workflows and shared dependencies remain unless explicitly removed.
18. Run the pre-publication audit, review the staged diff, and verify `main` branch protection is adjusted only by the repository owner when publication is requested. No GitHub Actions, force push, additional branches or private runtime data should be included in the public release.

**Known limitation:** The v1.4 full GUI, input hooks, Windows DPAPI and PyInstaller packaging cannot be natively acceptance-tested in the Linux authoring environment. The release remains **Windows acceptance pending** until the above checks are completed on a Windows workstation.
