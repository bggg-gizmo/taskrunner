# Task Runner 1.3.0 — Recording, visual triggers, live capture, installation

**Developer:** Background Gremlin Group — *Creating Unique Tools for Unique Individuals*.

This release adds functionality to the existing Windows application without removing existing action types, scheduling features, database storage, icon, or the seven selectable vaporwave sounds.

## Task recording / playback

- In **New Task** or **Edit Task**, select **● Record actions / Replay**.
- Read the recording disclosure. The wizard hides; recording starts after a two-second preparation period.
- Perform the workflow in the real desktop application, including typing and waits for applications to open.
- Press **Ctrl+Shift+F12** to stop; review and insert the captured steps into the editable workflow.
- Timing is preserved as `delay_before`. When a new named window is encountered, a **Wait for Windows window** step is recorded too, so a slow launch isn't dependent solely on a captured timer.
- Existing **Save + Run now**, verification, retry and scheduling functionality executes the recorded sequence; the recording itself remains in memory until the user saves.
- Capture is limited to 30 minutes per session. Global recording cannot capture privileged UAC secure-desktop prompts, applications running in different security sessions, or all game/DirectX surfaces. Passwords entered during recording can be recorded in a text action. Avoid typing credentials during recording and review every generated step before saving.

## Event-based execution

- **Wait for visual change**: wait until a screen region changes or until a saved reference image appears/disappears.
- **Wait for text / code / output**: poll a window, browser element, clipboard, or file until text appears, disappears, or changes. Store the observation as a workflow variable.
- **Click on-screen image**: match a reference image on the current desktop and click its matched location. Supports multiple monitors and optional constrained search regions.
- The screenshot wizard has **Capture trigger area** for visual-change and image-matching steps.
- Each wait has a timeout, polling interval, and existing retry controls.

## Capturing output while it appears

- **Start live output / image capture** begins sampling changes while later actions execute.
- Supports window accessibility text, file text, text clipboard, full desktop or selected screen-region images, image clipboard changes, and a watched image-output directory. Completed image files are copied without changing the originals. Changed frames save as PNG; text revisions save as UTF-8 text.
- **Stop live output capture** stops the monitor and saves `capture-manifest.json` listing captured files; a workflow finishing or being cancelled also closes capture.
- **Save clipboard image** saves a rendered image currently in the clipboard to PNG.
- **Run process and continuously save output** captures a launched program's standard output and errors to a real log file as the process runs.
- Capture is explicitly enabled by workflow actions; it is not a permanent background screen recorder. Capture outputs remain local and must be reviewed before sharing.

## More resilient clicking

- Recorded desktop clicks keep absolute coordinates **and** window-relative positions, and try a stable UI Automation ID when the target exposes one.
- During replay, a named target window must exist; Task Runner doesn't silently click the old screen coordinates if the expected program is absent.
- Image-matched clicks can find targets that moved after recording. Use a distinctive crop and verification for reliable automation.

## Windows installation and uninstall

- Run `BUILD_WINDOWS.cmd`, then `INSTALL_WINDOWS.cmd` to install the compiled one-directory application per-user.
- Installer registers a Start Menu shortcut and a Windows **Installed Apps** uninstall entry.
- Run `UNINSTALL_WINDOWS.cmd` (or Installed Apps) to remove the application, registry entry, Start Menu shortcut, and its own scheduler heartbeat.
- Saved workflows and captures remain under `%LOCALAPPDATA%\TaskRunner` unless deletion is separately requested and confirmed with `DELETE`.
- Shared Python site-packages, shared Playwright browser cache, and unrelated programs remain untouched.

## Validation

Source and offline tests run on Linux; compiled Windows GUI, native global hooks, UI Automation and Installed Apps integration still require Windows acceptance testing. An older release compiling successfully does not establish that the new Windows functions have been validated on-device.
