# Task Runner v1.4.0 — Adaptive Precision, Visual Playback Debugger and Local Automation

**Background Gremlin Group — Creating Unique Tools for Unique Individuals**

Task Runner v1.4.0 extends the complete v1.3.0 source. The existing vaporwave interface, seven optional sound effects, task wizard, desktop recorder, browser actions, SQLite persistence, output capture, scheduler, Windows installer and uninstaller remain intact. No GitHub Actions are needed to build or test the app.

## Interactive playback and teaching

On the Dashboard choose **▶ Debug replay** to claim a selected task in paused debug mode. Task Runner opens Execution Logs and shows the currently pending action with controls for Pause, Continue, Step once, Retry failed step, Teach current click, and Emergency stop. Each debug step can save actual virtual-desktop before/after/failure screenshots to `%LOCALAPPDATA%\TaskRunner\debug-runs\run-N`. These captures are local and can include private material.

**Teach current click** requires the workflow to be paused at a click. It hides Task Runner, takes a fresh desktop screenshot, and lets the user select the correct target. The correction updates the saved task and the active execution's retry target. The operator must explicitly press Retry after a failed action; a failure never silently replays a potentially irreversible step. Press **Ctrl+Shift+F11** during an active Windows workflow to request emergency cancellation. The existing Ctrl+Shift+F12 recorder-stop hotkey remains unchanged.

## Adaptive Precision Engine

New click parameters let you select a reference image, a minimum visual correlation, an explicit timeout, strict verified targeting and whether to allow the legacy window-relative fallback. On Windows, Task Runner attempts a matching UI Automation ID, then a matching control name, then an image match restricted to the recorded window, followed by window-relative positioning if permitted. For compatibility, existing coordinate-only clicks continue working. **Strict targeting refuses an unidentified target.** Ambiguous images or controls are rejected instead of choosing randomly. DPI-awareness is requested before the Qt GUI starts so mixed-DPI screens use consistent physical coordinates.

## Event-driven observation and scheduling

The new **Wait for visible text (offline OCR)** action uses bundled RapidOCR ONNX models locally to recognize screen text in a user-selected region. It can wait for text to appear/disappear or change, enforce consecutive stable frames, and store recognized text in a workflow variable. The existing screen-change, Playwright, clipboard and file-based waits remain available.

A **When a file or folder changes** schedule detects creation, modification or removal. Monitoring is persistent across app restarts, with atomic SQLite claims to avoid duplicate workers. When the GUI is open the scheduler polls approximately every second; with the GUI closed the Windows Task Scheduler heartbeat is approximately once per minute. It is not presented as an instantaneous filesystem notification system.

## Output Gallery

The existing live capture actions remain unchanged. The new **Output Gallery** page opens selected local capture directories, lists image and text artifacts, previews images and UTF-8 output, identifies byte-identical files by SHA-256, and exports a private archive with a content manifest. Nothing is uploaded to the cloud. Archive creation requires explicit confirmation because captures can contain private desktop data.

## Checkpoint recovery

The executor records verified, completed-step checkpoints. In Execution Logs, choose a failed or cancelled run and **Resume failed run** to review the checkpoint and opt in to a new continuation execution. A continuation refuses altered tasks, unstructured/nonlinear branching, lost browser/variable state, and runs with no recorded plan checksum. It does not automatically replay previous steps or claim that an incomplete side-effecting operation was rolled back.

## Modules, protected variables and portable workflow packages

**Run reusable task module** expands an existing saved task's actions before execution, preserving the current workflow variables and respecting recursion and size limits. Nested modules with cycles are rejected. Module-level retry/verification must be specified on the child actions, not silently discarded during expansion.

**Local credential vault** uses current-user Windows DPAPI encryption. Use Settings to store/update or delete a named secret, then **Read protected vault credential** to load it into a workflow variable. Encrypted vault files are stored only under the user's data directory and excluded from repository exports. Running an action that types a secret can still expose it to the intended target program or user-authorized output; secret values should not be recorded into ordinary workflow text fields.

**Portable packages** (`.trpkg`) include a root workflow, referenced module jobs and attached reference images with SHA-256 checksums. Script assets are included only when explicitly selected. Imports reject invalid paths, symlinks, mismatched hashes, missing modules and oversized archives; all imported tasks are disabled for manual review. Existing JSON import/export remains available.

## Windows installation and build

`BUILD_WINDOWS.cmd` checks shared dependencies, runs the regression suite, builds a PyInstaller one-directory EXE, bundles Chromium and offline RapidOCR ONNX resources, and runs the packaged self-test. The Windows installer and uninstaller are retained. The self-test checks OCR model initialization but is **not** evidence that every Windows input-hook or UI Automation target works on every PC.

The archive contains the complete public v1.3.0 source in `old builds/v1.3.0/` and retains `old builds/v1.2.1/` without overwriting them. The main repository remains unchanged until explicitly requested for a push.

## Validation status

The local Linux source regression suite passes, including new tests for debugging, click-target certainty, SQLite migration/claims, module expansion, DPAPI storage adapters, offline OCR logic, file-change scheduling, capture archives, portable package tamper detection, and checkpoint continuation. Actual Windows GUI screenshots and an interactive Windows EXE/installer acceptance pass remain required before claiming production verification on Windows.
